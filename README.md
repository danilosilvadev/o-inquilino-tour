# O Inquilino — Tour

Dani's poem *O Inquilino* staged as a single continuous piece: **6 cantos, 24
parts, 93 paragraphs**, read end to end without ever loading a page twice.

The structural idea is borrowed from [santionispirits.com](https://santionispirits.com)
(Active Theory / Hydra): there is no page, there is one continuous world, and
scrolling is time. Everything else comes from the poem.

---

## Run it

```bash
npm install
npm run dev      # http://127.0.0.1:5180
npm run build    # static bundle in dist/
```

- `/` starts at Canto I, part ✳ and runs to the end of the poem.
- `?part=III-2` opens any part directly.
- `?debug` exposes `SCENE`, `SCRUB`, `PART`, `JUMP(t)`, `TICK(n)`, `GOTO(i)`.
- `?auto` skips the threshold (used by the test sweep).
- `/sweep.html` loads all 24 parts in turn and reports failures.

## The rule

**Nothing illustrates the text.** The first version of this did — a line about a
heart got a heart prop, a line about scratching got scratch marks — and it read
as a picture book. The figure now never performs. He stands, and barely: breath,
and the small sway nobody can suppress. He is a *tenant*; things happen to him.

What changes between parts is what the room does to him, drawn from a grammar
of ten moves:

| move | what it does |
|---|---|
| `double` | the same body, a moment behind itself |
| `afterimage` | he leaves copies of himself where he has been |
| `erase` | the lucidity does not light him, it takes him off the paper |
| `pulse` | the room throbs on a beat he does not share |
| `press` | the corridor closes in |
| `tilt` | the room stops being level |
| `sink` | the floor takes him |
| `cold` | the light goes blue and thin |
| `swarm` | the dark has grain moving in it |
| `stretch` | the space gets longer than it should be |

Each part composes its own mixture. The table lives in `tools/build-parts.py`
and is the score for the images — it is read from the poem, not generated.

## The stage

No renderer, no dependencies. An SVG landscape, a skeleton drawn with a dozen
lines, and the stanza in HTML over the top. 34 KB, 12 KB gzipped.

**Six landscapes, one per canto.** The first build had one corridor behind the
whole poem, so twenty-four parts looked identical while the writing changed
completely. Each canto now has its own dark, near-empty place:

| canto | the place |
|---|---|
| I | a floor and one lit doorway, far off, narrowing |
| II | two masses pressing in, and a ceiling coming down |
| III | no ground at all — a void, a slow drip, points drifting apart |
| IV | a heavy ground that swells like something breathes under it |
| V | the only canto with someone else in it; the floor lifts, then two holes |
| VI | an empty field, ash falling, a ring worn into the ground |

None of them illustrate a line. They are the shape of the feeling the canto
happens inside. The figure never mimes the words either — each canto only
changes how he holds himself while he stands in it.

`src/stage/Skeleton.js` is all angles, so a pose is just numbers and poses
interpolate. `src/stage/Landscapes.js` holds the six.


## Sound

**The score** is one continuous thread. `tools/cut-score.py` allocates the
recording across all 24 parts in proportion to how much text each carries, laid
end to end, so part N+1 resumes exactly where part N stopped. Handover between
parts keeps the audio context alive so the thread is never restarted.

**The narration** is the poem read aloud in Portuguese, one clip per paragraph,
generated by `tools/narrate.py` (Kyutai pocket-tts). The score ducks underneath
the voice and eases back after.

```bash
python3 tools/cut-score.py --list          # the whole music map
python3 tools/cut-score.py --part IV-2     # cut one part's slice
python3 tools/narrate.py --all             # every part, one model load
python3 tools/narrate.py --part I-1 --voice-wav ~/dani.wav   # clone a real voice
```

The narration is currently a stock voice (`rafael`). Point `--voice-wav` at
20–30 seconds of Dani speaking and it becomes his.

## Structure

```
src/
  main.js                 boot, threshold, loader, render loop, part handover
  config/base.json        the shared look — tune the piece here
  config/figure-back.json the cutout rig: parts, pivots, joints
  config/vo-*.json        narration manifests, one per part
  poem/parts.json         all 24 parts: beats, lines, camera stations, moves
  scenes/PartScene.js     the room, the swarm, the figures, the words
  core/
    CutoutFigure.js       rigid cutout animation of the drawing
    Scrubber.js           the virtual playhead — the document never scrolls
    Post.js               film pass: iris, tremor, bleed, grain, vignette
    Score.js              this part's slice of the Adagio
    Narration.js          the poem read aloud, with the score ducking
    Heartbeat.js          synthesised lub-dub and room tone
tools/                    the pipeline: poem → stage directions → assets
```

## Testing

`sweep.html` loads every part in an iframe, runs its whole timeline, and checks
the text built, the figure loaded and WebGL is alive. It reports per-part status
plus whether that part's music and narration exist on disk.

Note: a hidden browser tab suspends `requestAnimationFrame` completely. That is
why the render loop is split into `frame()` (scheduling) and `step()` (work),
and why the transition fade runs on a timer instead — a fade that depends on rAF
strands a reader who switches tabs mid-handover on a black screen.

## Not done

- **Dani's own voice.** Needs a recording; the flag is wired.
- **The seated drawing** is extracted (`public/character/seated.png`) but unused.
  Canto II's *"Passo os dias preso no meu quarto"* is almost a description of it.
- **The profile views** are extracted and unused. A part that wants a forward
  lean needs the side view, because from behind a lean is foreshortened away.
- **Per-part tuning.** All 24 parts render and are staged from the moves table,
  but only Canto I has been looked at frame by frame.
- **Music licensing.** The Adagio is a YouTube rip of a specific performance.
  Fine locally; a public version needs a recording with clear rights. The cut
  points are data, so swapping the source is one path change.
